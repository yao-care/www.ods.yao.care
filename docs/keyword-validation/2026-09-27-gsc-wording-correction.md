# 2026-09-27：用 GSC 實際查詢字回頭校正標題用字（選字四步的第 4 步）

起因：站台上線滿月後第一次逐頁比對 GSC 的 query × page，發現**排名不差但用字對不上**的一批頁。
近 28 天（08-27～09-24）全站曝光 10,509、點擊 217（前一個 28 天是 24 曝光、0 點擊），
流量集中在 `/templates/`（66 點擊）、`/receipt/`（59）、`/private-documents/`（32）。

## 這一輪刻意不做的：不為每個 .docx 各開一個下載落地頁

`public/downloads/**` 有 62 個 .docx，其中 46 個已經有自己的內容頁（cases 23、citizens 9、private 14），
另外 16 個空白範本掛在 `/templates/` 一頁上。「每個檔各開一頁、鎖定〈文別〉word 下載」這個念頭被下面三件事否掉：

- **公文族群的單一文別沒有量**：`2026-08-27-combo-zero-resolved.md` 量到「公文範本」是實訊 0
  （中文＋中文組合，不是 API 切不出來的那種 0），市場的詞是「公文格式」300；
  「開會通知單」主詞本身只有 21。拆成 5 頁是把 `/templates/` 自己的訊號切碎去搶 21 的字。
  同一份文件對「公文格式 word」的處置已經是「站上 `/templates/` 已經在做這個意圖，**維持現狀即可**」。
- **民間書件那幾個文別有量，但站上已經各有一頁在吃**（委託書 1,865／切結書 958／和解書 829／
  借據範本 858）。再開一個「委託書空白範本」頁是自己跟自己互搶，而 09-26 的反思才剛確認
  全站沒有任何一個查詢對應兩個以上網址。
- 同型判例三次都選不另開頁：出差旅費的相鄰字（`2026-08-26-demand.md`）、問句型
  （`2026-08-27-combo-zero-resolved.md`）、人工智慧基本法（`2026-08-28-demand.md`）。

依據的用字結論（`2026-08-27-combo-zero-resolved.md` 第 4 點）：
**「範本／範例」後綴在民間書件是主要搜法**（借據範本 858 > 借據 435、收據範本 647、
委託書範本 347、離婚協議書範本 374），**在公文則不是**（公文範本 0 而公文格式 300）。
所以這一輪民間書件那批一律改成「範本」，公文那批**沒有動「範例」兩個字**，
只把機關實際在說的詞（內部簽呈、敘獎公文、會勘公文、借用場地公文、會議通知單）補進標題。

## 第二輪（同日）：用字校正只是零錢，真正的作用點是「高曝光頁上沒有檔可下載」

用字校正做完之後，用同一份資料算了一次上限，結論是它不可能是主菜：

| | 曝光（近 28 天） | 點擊 | 點閱率 |
|---|---|---|---|
| 全站 | 10,509 | 217 | 2.06% |
| **今天改標題的那 19 頁合計** | 638（全站 6.1%） | 44 | 6.90% |
| `/numbers/` | 6,817（全站 65%） | 15 | **0.22%** |
| `/receipt/` | 1,796 | 59 | 3.29% |
| `/templates/` | 456（全站 4.3%） | 66（全站 **30%**） | **14.47%** |

三件事擺在一起就看得出作用點在哪：

1. 改標題那 19 頁的點閱率**本來就已經 6.9%**，比全站平均好三倍。就算再翻一倍也只多 20 幾次點擊。
2. 全站 65% 的曝光壓在 `/numbers/` 一頁，而它幾乎不轉換（0.22%）。
3. **唯一已經被實證的轉換機制是「有檔可下載」**：`/templates/` 用 4.3% 的曝光拿下 30% 的點擊，
   而 09-26 的反思也記著它的 Word 類查詢點閱率 9～31%。

而站上 62 個 Word 檔裡**一份領據與一張大寫對照表都沒有**，
偏偏「領據範本word」「個人領據範本」「領據範本」這些字已經在搜、而且就落在 `/receipt/`。

### 做了什麼

- `/receipt/` 新增第一節「領據範本下載（Word）」，兩份檔：空白（五款留成待填）與範例
  （社區發展協會領補助款）。欄位定義抽到 `src/data/receipt.js`，網頁與 Word 吃同一份
  （比照 `meeting.js`／`note.js`，避免「網頁對、Word 錯」）。標題補上「領據範本下載」。
- `/numbers/` 新增第三節「對照表下載（Word）」，一份可列印的對照表：0–9、位數、
  進位與補零範例、第十三點原文。換算值由 `uppercase-number.js` 產生，不另抄一份。
- 產生器放在新的 `scripts/lib/reference-docs.mjs`，**刻意不放進 `gov-format.mjs`** ——
  這兩份不在政府文書格式參考規範裡，放進去會讓人以為它們的版面也有官方出處。
- `downloads.json` 多一群 `extras`（不併進 `templates`，那個陣列是依文別分三族群的）。
  `/templates/` 新增「表單與對照表」一節，樞紐仍然只有那一頁。
- `scripts/lib/lastmod.mjs` 的 `SECTION_DATA` 補 `receipt` 與 `numbers` 兩段。

### 刻意沒動的

`/numbers/` 的**標題與描述一個字都沒改**。那頁 09-22 才調過一次，冷卻期到 09-29，
現在動摘要會讓那次調整的效果無法歸因。等 09-29 之後再決定要不要把「可下載對照表」寫進摘要
—— 在那之前，SERP 上不會看到有檔可下載，只有點進來的人看得到。

### 怎麼驗這一輪有沒有用

看的是這兩頁的**點閱率**，不是名次：`/receipt/` 從 3.29%、`/numbers/` 從 0.22% 起算。
`/templates/` 已驗證的 14.47% 是上限參考值，不是預期值。
GA4 那邊另有 `file_download` 事件（file_name／file_extension／link_url／link_text），
可以直接看這三個檔被抓了幾次 —— 那是比點閱率更直接的訊號。
