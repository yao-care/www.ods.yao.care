新增頁面後務必自己對一次：

```bash
node -e "const c=require('/root/seo-ops/sites/ods.yao.care.json');
fetch('https://www.ods.yao.care/sitemap-0.xml').then(r=>r.text()).then(x=>{

  const t=new Set(c.trackUrls); console.log('漏的：', live.filter(u=>!t.has(u)))})"
```

**結構性的修法已做，但形狀跟原本想的相反**（2026-08-26，用戶指示執行）：
直覺是「候選集直接讀 sitemap」，動手前先量全隊，結論推翻了它 ——
各站 sitemap 筆數 `folk.tw 12,303／sutta.io 2,858／appi.news 1,617／weiqi.kids 1,595…`，
而 **Indexing API 配額是專案層級 200／日、14 站共用**。對內容型站台，
`trackUrls` 是「我要盯的那幾頁」不是「全站」，那是刻意的；直接讀 sitemap 會當場炸掉全隊配額。
真正 `trackUrls == sitemap` 的只有三站（arthurs.tw、forme-cro.org、ods.yao.care）。

所以做成 **opt-in ＋ 硬上限**：`indexPing.fromSitemap` 設了才讀，上限 300 筆、
超過或讀不到 sitemap 一律 exit 1 中止（不退回舊清單）。目前只有本站開啟，沒設的站行為完全不變。
seo-ops commit `c99d45c`，教訓寫在 `MAINTENANCE.md` 教訓 #27。

⚠️ **`trackUrls` 仍要維護** —— seo-collect 用它決定每天量哪些頁的 coverage，那是另一個消費端。
