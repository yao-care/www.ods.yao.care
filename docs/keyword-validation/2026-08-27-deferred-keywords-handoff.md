# 有量但目前未追的關鍵字：交接清單

> **給誰看**：要接手評估這些字該不該做的人。你不需要先熟悉本站。
> **建立**：2026-08-27。**判定基準日**：需求量 2026-05-28 ~ 2026-08-25。
> **這份不含**「刻意不產出」那一類（本票、存證信函用紙等）—— 那一類 2026-08-27 已改為要產出，不在本檔範圍。

## 一、先讀：這個站在賣什麼，判準才有意義

`www.ods.yao.care` 是**公文案例庫**：承辦開案時搜「補助核銷 公文 範例」，站上給他公文全文＋逐條格式檢核＋Word 下載。
產品（公文 AI 訂閱）是配角。所以判斷一個字要不要做，問的不是「有沒有人搜」，而是
**「搜這個字的人，要的是不是一份寫好的文書」**。

## 二、量是怎麼來的，以及它的三個判讀邊界

```bash
node /root/seo-ops/bin/keyword-demand.mjs --file <候選字.json>   # 一批字
node /root/seo-ops/bin/keyword-demand.mjs --site ods.yao.care    # 現有釘選字
```

資料源是 **Bing Webmaster Keyword API**（`--country tw --language zh-TW`），唯讀。

1. **這是 Bing 不是 Google**。台灣市佔低，**只能看相對大小與「是不是 0」**，不能當流量預估。
2. **多字組合的 0 不可靠**。實測「公文格式」300 但「公文格式 word」0 —— 量在主詞不在組合，Bing 沒把組合切出來。**只有單字頭部詞的 0 才是實訊。**
3. **有量 ≠ 打得贏。** 一定要再實搜一次看 SERP 前排是誰。本檔每一列都標了 SERP 由誰、何時觀察。

## 三、選字四步（照順序，不要跳）

1. `keyword-demand.mjs` 量。**單字頭部詞判 0 就不做。**
2. 有量的字實搜 SERP，看前排是不是搶得到的。
   ⚠️ 這一步吃 WebSearch 額度（session 上限預設 200，用罄就換 session）。
   **用 curl 抓 Bing 結果頁代替行不通**，回來的是機器人防護頁，內容與查詢無關。
3. `grep -r` 站台 repo，確認站上用的是不是同一個詞（簽 vs 簽呈、請撥 vs 請款）。
4. 上線後用 GSC 實際 query 回頭校正。**回頭校正日 2026-09-20。**

## 四、法規名稱字的額外判準（三條，缺一不做）

2026-08-26 用「國內出差旅費報支要點」對照出來的。遇到法規名稱字先套這三條：

1. **它在不在全國法規資料庫（`law.moj.gov.tw`）？** 在 → 有一個「條文最全、連結最多」的對手佔著第一名，重製條文打不贏。**行政規則不進那個資料庫**，前排就會散成各機關各自上傳的 PDF，那才有得搶。
2. **對手是不是 PDF？** PDF 沒錨點、沒結構化資料、手機難讀，我們的 HTML 才有差異化空間。
3. **這個字接不接得上站上已有的頁？** 接不上就沒有內鏈，只靠 sitemap 不會被爬。

> 正面案例：「國內出差旅費報支要點」（1,034）三條全中 → 已做成 `/travel-expense/`。
> 反面就是下表第一組。

### 5.5 站上用詞與市場用詞不一致（判定：**待處理，不是不做**）

**這一組跟上面性質不同，接手的人請優先看這裡** —— 有量、意圖也對，只是我們用了別的詞：

| 市場在搜 | Bing exact | 站上叫什麼 | 該怎麼辦 |
|---|---|---|---|
| 簽呈 | 732 | 一律叫「簽」 | 站上有頁，但標題與內文用「簽」。要不要在標題帶入「簽呈」是**選字決定**，不是內容決定 |
| 請款單 | 943 | 我們叫「請撥」 | 同上 |
| 請購單 | 322 | 標題寫「請購」 | 同上 |
| 文書處理手冊 | 732 | 引用很多次，**沒有落地頁** | 這是唯一「有量、意圖對、對手可能搶得到、站上卻沒有落地頁」的字，值得先跑一次四步 |

⚠️ 動這一組之前先跑第 3 步（`grep -r` repo）確認站上實際用詞，
並注意公文用語有正式性要求——不能為了 SEO 把「簽」全站改叫「簽呈」。

## 六、不在本檔、但接手時會撞到的兩件事

1. **多字組合字那一批**（公文格式 word、公文範本下載、開會通知單範例、補助核銷公文範例、存證信函怎麼寫…）量測為 0，但**那個 0 不可靠**（判讀邊界 2）。站上這些頁反而都有做。**不要拿那個 0 去砍頁面。**
2. **GSC 目前幾乎沒有資料**：2026-08-27 實查，本站近 30 天只有 3 個 query、5 次曝光、0 點擊（`採購公文範例` 46 名、`文別` 9 名、`諒達公文` 86 名）。所以第 4 步（GSC 回頭校正）在 2026-09-20 之前做不了，別拿現在的數字下結論。
